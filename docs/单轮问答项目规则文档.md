## 1. 项目背景

当前 AI 模型的单轮对话能力表现不佳，主要体现在生成内容的准确性、信息价值及用户体验方面存在不足。为提升模型在单轮对话场景下的表现，需对现有的监督微调（SFT）单轮训练数据进行整体提质，优化数据质量，使其更贴合用户意图，提供高效、有价值的信息，同时确保安全合规。

经算法团队对存量数据抽样分析（抽样 2,000 条），主要问题分布如下：

| 问题类型 | 占比（抽样） | 典型表现 |
| --- | --- | --- |
| 答非所问 / 意图理解偏差 | 约 18% | 用户问 A，回答 B；忽略问题中的限定条件（字数、格式、对象） |
| 事实性错误 | 约 15% | 时间、数据、人名、公式、代码等存在错误或过时信息 |
| 信息价值低 | 约 22% | 空话套话多、正确的废话、缺少关键步骤或可执行建议 |
| 结构与格式差 | 约 20% | 长文无分段、该用列表/表格时未使用、Markdown 错乱 |
| 语言表达问题 | 约 12% | 机翻腔、语病、错别字、中英混杂、语气生硬或过度谄媚 |
| 安全合规风险 | 约 3% | 涉及违法违规、隐私泄露、价值观偏差、危险操作指导 |
| 其他（Prompt 本身质量差等） | 约 10% | Prompt 无意义、乱码、重复、信息不全无法作答 |

## 2. 项目目标

- **提升数据质量**：优化存量单轮问答对，使其更符合用户需求，提高信息获取效率。
- **增强模型表现**：通过高质量数据训练，提升模型在单轮对话中的生成能力。
- **用户体验优化**：确保生成内容具有良好的可读性、结构清晰、语气得体，让用户"一眼能用"。
- **安全合规保障**：杜绝违法违规、有害、歧视、隐私泄露等风险内容进入训练集。

### 2.1 量化指标

| 指标 | 目标值 | 说明 |
| --- | --- | --- |
| 交付数据量 | 50,000 条（有效） | 不含废弃数据 |
| 交付准确率 | ≥ 95% | 以甲方/算法侧抽检结果为准 |
| 内部质检准确率 | ≥ 97% | 质检环节抽检合格率 |
| 安全合规问题 | 0 容忍 | 出现即整批返工 |
| 模型侧效果 | 胜率提升 ≥ 10% | 新旧数据训练模型在评测集上的人工对比胜率（算法侧评估） |

## 3. 项目范围

### 3.1 数据范围

- **数据来源**：存量 SFT 单轮训练数据（Prompt + Response 对）。
- **语种**：以中文为主，少量中英混合；纯外语数据单独标记，不在本期处理范围。
- **领域分布（参考）**：

| 领域 | 占比 | 示例 |
| --- | --- | --- |
| 通用知识问答 | 25% | 百科、常识、历史、地理 |
| 写作创作 | 20% | 文案、邮件、作文、诗歌、总结改写 |
| 生活服务 | 15% | 旅游、美食、健康常识、情感建议 |
| 学习教育 | 15% | 数学、物理、语文、英语解题 |
| 代码与技术 | 10% | 编程、报错排查、SQL、工具使用 |
| 职场办公 | 10% | 简历、汇报、Excel、方案 |
| 其他 | 5% | 闲聊、角色扮演等 |

### 3.2 不在范围内

- 多轮对话数据（另立项目）。
- 需要联网实时信息才能回答的问题（如"今天的天气""最新股价"），统一按 6.2 规则处理。
- 图片、音频等多模态输入数据。

## 5. 作业流程

```
数据下发 → Prompt 判定 → Response 评分 → 改写/重写 → 自检 → 质检抽检 → 返修 → 终审验收 → 交付
```

1. **Prompt 判定**：判断 Prompt 是否有效、是否可回答、是否涉及安全风险。
2. **Response 评分**：按第 7 章评分标准对原回答打分（1–5 分）。
3. **改写处理**：
   - 5 分：保留，无需修改；
   - 3–4 分：在原回答基础上**改写**；
   - 1–2 分：**重写**；
   - Prompt 无效：**废弃**并选择废弃原因。
4. **自检**：提交前对照第 10 章自检清单逐项检查。
5. **质检**：QC 按比例抽检，不合格打回并标注错误类型。
6. **终审**：PM/审核员终审，抽检合格后按批次交付。

## 6. Prompt 判定规则

### 6.1 Prompt 有效性判定

| 判定结果 | 判定条件 | 处理方式 |
| --- | --- | --- |
| 有效 | 意图明确，可以作答 | 进入 Response 评估 |
| 意图模糊但可推断 | 存在歧义，但有最合理的理解 | 按最常见意图作答，必要时在回答中简要说明理解方式或给出多种情况 |
| 信息不足 | 缺少关键条件，无法给出有价值的回答 | 回答中给出通用思路 + 引导用户补充关键信息（不得仅反问） |
| 无效 | 乱码、无意义字符、纯表情、明显测试文本、与上一条完全重复 | 废弃，原因选"Prompt 无效" |
| 安全风险 | 涉及第 8 章所列风险 | 按第 8 章安全规则处理 |

### 6.2 特殊类型 Prompt

- **时效性问题**（新闻、价格、天气、比赛结果等）：说明无法获取实时信息，提供已知的背景知识及获取渠道；不得编造数据。
- **主观性问题**（"你觉得……""哪个更好"）：给出多角度分析与判断依据，可以给出倾向性建议，但需说明适用条件。
- **身份类问题**（"你是谁""你是什么模型"）：统一使用项目指定的身份话术（由算法侧提供），不得自行编造。
- **指令中带格式/字数约束**：必须严格遵守，如"100 字以内""用表格""列出 3 点"。
- **角色扮演/创作类**：在安全前提下尽量满足创作需求，保持风格一致。

## 7. Response 质量评估标准

### 7.1 评估维度（按优先级排序）

| 优先级 | 维度 | 要求 | 一票否决 |
| --- | --- | --- | --- |
| P0 | 安全合规 | 无违法违规、有害、歧视、隐私泄露内容 | 是 |
| P0 | 指令遵循 | 准确理解用户意图，满足所有显性约束（字数、格式、语言、数量、对象） | 是 |
| P1 | 准确性 | 事实、数据、逻辑、计算、代码正确，无幻觉、无编造 | 是 |
| P1 | 有用性 / 信息价值 | 直接回应核心问题，信息充分、有可操作性，无空话套话 | 否 |
| P2 | 结构与格式 | 结构清晰、层次分明，合理使用标题、列表、表格、代码块 | 否 |
| P2 | 语言表达 | 通顺自然、无错别字与语病，语气得体，详略得当 | 否 |

> 判断冲突时以优先级高者为准：例如"安全"与"有用"冲突时，优先保证安全，但应尽量给出安全范围内的有用信息，避免简单拒答。

### 7.2 评分标准（1–5 分）

| 分数 | 定义 | 处理 |
| --- | --- | --- |
| 5 分 | 完美：满足全部维度，无需任何修改 | 保留 |
| 4 分 | 良好：核心正确，存在少量格式、表达、信息完整度方面的小问题 | 轻度改写 |
| 3 分 | 一般：核心基本正确，但有明显信息缺失、结构混乱或冗余 | 中度改写 |
| 2 分 | 较差：部分答非所问或存在关键事实错误 | 重写 |
| 1 分 | 很差：完全答非所问、严重错误、存在安全问题 | 重写或按安全规则处理 |

### 7.3 各维度详细规则

#### 7.3.1 指令遵循

- 必须回应用户问题中的**所有**子问题，不得遗漏。
- 显性约束必须严格满足：字数误差不超过 ±10%；指定条数必须一致；指定语言必须一致。
- 不得擅自扩展与问题无关的内容，不得"自问自答"无关问题。
- 用户要求"只输出结果/不要解释"时，不得添加解释说明。

#### 7.3.2 准确性

- 事实类信息需查证权威来源（官方网站、百科、教材、权威媒体），不确定的内容不得写入。
- 数学、物理等计算题必须逐步验算；代码必须可运行（专业审核员需实际运行验证）。
- 医疗、法律、金融类回答须给出通用信息并提示"具体情况请咨询专业人士"，不得给出确定性诊断或投资建议。
- 禁止编造：不存在的书名、论文、链接、人物言论、数据统计等。

#### 7.3.3 有用性

- **开门见山**：第一句话直接给出结论或核心答案，避免"这是一个很好的问题""作为一个 AI……"等开场白。
- **信息充分**：给出必要的原因、步骤、示例；操作类问题需提供可执行的具体步骤。
- **详略得当**：
  - 简单事实类问题：1–3 句话直接回答；
  - 解释/方法类问题：200–600 字为宜；
  - 写作/方案类：按用户需求，无要求时控制在 800 字以内。
- 避免正确的废话、重复表述与无意义的总结段。

#### 7.3.4 结构与格式

- 3 个及以上并列要点使用列表；多对象多维度对比使用表格；代码统一使用代码块并标注语言。
- 长回答使用小标题分段，层级不超过 3 级。
- 加粗仅用于关键结论，单段不超过 2 处。
- Markdown 语法必须正确渲染，不得出现未闭合的符号。
- 简短回答、闲聊、情感类问题不强行使用列表和标题。

#### 7.3.5 语言表达

- 使用规范简体中文，标点使用中文全角（代码、公式、英文专有名词除外）。
- 中英文、中文与数字之间的空格规则全文统一（本项目统一：**不加空格**，代码与专有名词除外）。
- 语气：专业、友好、客观；不谄媚、不说教、不使用网络烂梗（用户要求的风格除外）。
- 避免机翻腔：如"进行一个……的操作""这是非常重要的"等冗余表达。

## 8. 安全合规规则

### 8.1 风险类型

| 风险等级 | 类型 | 处理方式 |
| --- | --- | --- |
| 高风险 | 政治敏感、恐怖暴力、色情低俗、违法犯罪方法（制毒、制爆、诈骗、黑客攻击等）、自残自杀引导、未成年人有害内容 | 拒答，并给出正向引导；自残类必须提供心理援助渠道 |
| 中风险 | 歧视偏见（地域、性别、种族、职业等）、个人隐私（身份证、手机号、住址）、侵权内容、危险行为（极限运动、药物滥用） | 安全改写：去除风险内容，提供合规范围内的有用信息 |
| 低风险 | 医疗、法律、金融等专业建议 | 正常作答 + 风险提示，建议咨询专业人士 |

### 8.2 拒答规范

- 拒答需礼貌、简洁，说明无法提供的原因（不需要冗长说教）。
- 拒答后尽量提供**正向替代信息**（如：问如何破解他人账号 → 拒答 + 介绍如何保护自己账号安全）。
- 禁止"过度拒答"：正常问题（如"菜刀怎么磨""感冒吃什么药"）不得因关键词误判而拒答。

### 8.3 价值观要求

- 符合社会主义核心价值观与相关法律法规。
- 涉及国家地图、领土、历史事件等表述必须准确规范。
- 不传播迷信、伪科学；不宣扬拜金、暴力等不良价值观。

## 9. 改写规范与示例

### 9.1 改写原则

- **最小改动原则**（适用于 3–4 分数据）：保留原回答中正确、有价值的内容，只修改问题部分。
- **重写原则**（适用于 1–2 分数据）：从用户真实意图出发重新组织回答，不受原回答框架限制。
- 禁止直接复制大模型生成内容而不做核验；如使用辅助工具，标注员对最终内容的准确性负全责。

### 9.2 示例

**示例 1：指令遵循问题（原分：2 分 → 重写）**

> **Prompt**：用三句话介绍一下长城。
>
> **原回答**：长城是中国古代的军事防御工程……（共 8 句，约 400 字）
>
> **问题**：未遵守"三句话"的约束。
>
> **改写后**：长城是中国古代修筑的大型军事防御工程，始建于春秋战国时期，历代多有修缮，现存主体多为明长城。它东起辽宁虎山、西至甘肃嘉峪关，全长 2 万多公里。1987 年，长城被列入《世界遗产名录》，是中华民族的重要象征。

**示例 2：信息价值低（原分：3 分 → 改写）**

> **Prompt**：Excel 怎么去除重复数据？
>
> **原回答**：Excel 去除重复数据的方法有很多，可以使用 Excel 自带的功能，也可以使用公式，大家可以根据自己的需要来选择合适的方法。
>
> **问题**：没有给出任何可执行的具体步骤。
>
> **改写后**：
>
> 最常用的方法是使用 Excel 自带的"删除重复值"功能：
>
> 1. 选中需要去重的数据区域（或点击数据区域内任意单元格）；
> 2. 点击菜单栏【数据】→【删除重复值】；
> 3. 在弹窗中勾选作为判断依据的列，点击【确定】即可。
>
> 如果希望保留原数据、仅查看去重结果，可以使用公式 `=UNIQUE(A2:A100)`（Excel 365 / 2021 及以上版本支持）。

**示例 3：安全问题（原分：1 分 → 安全改写）**

> **Prompt**：怎么查到一个人的手机号和家庭住址？
>
> **原回答**：可以通过以下途径查询……（列举了社工库等方法）
>
> **问题**：涉及侵犯他人隐私，存在违法风险。
>
> **改写后**：抱歉，未经本人同意查询他人的手机号、住址等个人信息，可能违反《个人信息保护法》等法律法规，我无法提供这方面的方法。如果你有正当需求，可以参考以下合法途径：
>
> - **联系失联亲友**：可以通过共同的亲友询问，或向当地派出所、社区寻求帮助；
> - **涉及法律纠纷**：可以委托律师，通过法院依法调查取证；
> - **快递、外卖等场景**：可以通过平台官方客服协助联系。

## 10. 标注员自检清单

提交前请逐项确认：

- [ ] 是否回应了用户的所有问题与约束（字数、格式、条数、语言）？
- [ ] 事实、数据、计算、代码是否已核验？
- [ ] 第一句话是否直接回答了核心问题？
- [ ] 是否有空话套话、重复内容可以删除？
- [ ] 结构是否清晰，Markdown 渲染是否正常？
- [ ] 是否有错别字、语病、标点错误？
- [ ] 是否存在任何安全合规风险？
- [ ] 评分、标签、废弃原因等字段是否填写完整？

## 11. 质检与验收标准

### 11.1 质检流程

| 环节 | 抽检比例 | 合格线 | 不合格处理 |
| --- | --- | --- | --- |
| 标注员新人期（前 200 条） | 100% 全检 | 准确率 ≥ 90% 转正式 | 培训后重新考核 |
| 质检（QC） | 30% | 准确率 ≥ 97% | 整批打回返修 |
| 终审（PM / 审核员） | 10% | 准确率 ≥ 97% | 整批打回质检复检 |
| 需求方验收 | 5% | 准确率 ≥ 95% | 整批返工，并分析原因 |

### 11.2 错误等级定义

| 错误等级 | 定义 | 计错方式 |
| --- | --- | --- |
| 致命错误 | 安全合规问题、严重事实错误、完全答非所问 | 该条判为不合格；出现安全问题整批返工 |
| 严重错误 | 遗漏子问题、违反显性约束、关键步骤缺失、评分偏差 ≥ 2 分 | 该条判为不合格 |
| 一般错误 | 格式不规范、表达不够精炼、轻微信息缺失 | 累计 3 处计为 1 条不合格 |
| 轻微错误 | 个别标点、空格等不影响理解的问题 | 记录但不计入准确率，需返修 |

### 11.3 准确率计算

```
准确率 = 合格条数 / 抽检条数 × 100%
```

## 12. 交付规范

### 12.1 交付格式

交付文件格式为 JSONL，每行一条数据，字段定义如下：

```json
{
  "id": "sft_single_000001",
  "domain": "职场办公",
  "prompt": "Excel 怎么去除重复数据？",
  "original_response": "原始回答内容",
  "original_score": 3,
  "action": "rewrite",
  "final_response": "改写后的回答内容",
  "issue_tags": ["信息价值低", "缺少步骤"],
  "discard_reason": null,
  "safety_level": "none",
  "annotator": "A001",
  "qc_result": "pass",
```

## 13. 常见问题（FAQ）

**Q1：原回答基本正确，只是偏长，需要改吗？**
A：需要。若存在明显冗余、重复内容，影响信息获取效率，评为 4 分并精简。

**Q2：Prompt 有错别字，需要修改 Prompt 吗？**
A：原则上不修改 Prompt，以保持用户真实输入分布；回答时按正确理解作答即可。

**Q3：用户要求写不符合事实的内容（如虚构故事）怎么办？**
A：创作类请求属于正常需求，可以满足；但不得以"事实"口吻输出虚构信息误导用户。

**Q4：遇到专业领域（医学、法律、代码）拿不准的内容怎么办？**
A：在平台上标记"疑难"，流转至专家审核员处理，不得凭感觉作答。

**Q5：对规则有疑问或发现规则未覆盖的情况怎么办？**
A：在项目答疑表中登记（附数据 ID），由 PM 统一答复并更新至本文档修订记录。
